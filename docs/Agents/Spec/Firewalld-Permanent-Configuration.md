# Permanent firewalld configuration

Target: Debian 13, firewalld 2.3.1. This is the implementation and acceptance plan, **not an assertion that any row has passed**. Authorities: the [2.3.1 object parsers](https://github.com/firewalld/firewalld/tree/v2.3.1/src/firewall/core/io), [rich language](https://github.com/firewalld/firewalld/blob/v2.3.1/src/firewall/core/rich.py), [daemon configuration reader](https://github.com/firewalld/firewalld/blob/v2.3.1/src/firewall/core/io/firewalld_conf.py), and [Debian manual](https://manpages.debian.org/trixie/firewalld/firewalld.1.en.html). If an XSD predates the implementation, the installed daemon decides.

## Resource and migration contract

Each named definition, zone, policy, and daemon key has one owner. A reference within a declaration resolves to its declared owner or to an existing external definition; external references create no ownership. Preserve resource tokens/names, checkpoint IDs, journal owners and legacy wire defaults. Preview stays offline. See the explicit Docker gate migration below; upgrading must not silently restart a running Docker workload or remove an existing protective policy.

A port range belongs to its transport; a service describes traffic, not a listener. For example, a service admitting TCP 8440–8443 can be attached to a named source zone → `HOST` policy without granting traffic from that zone to any other zone. DNAT has an independent original transport/port and a destination address and/or port. Neither implies general forwarding. Rich-rule ordering and restrictions must survive wire and native round trips. A closed native vocabulary is not arbitrary XML, shell, paths or direct rules.

```fsharp
open Dorothy.DSL
open Dorothy.DSL.Firewalld

let api = Defined.service "example-api" {
    transportPorts [portRange 8440 8443 FirewalldTransport.Tcp]
}
let firewall = firewalld {
    api
    zone "clients" { interfaces ["vpn0"] }
    policy "clients-to-host" {
        ingressZones ["clients"]
        egressZones ["HOST"]
        services [api.Name]
        priority -2
    }
}
```

`services ["ssh"]` references an external definition if the host does not declare `Defined.service "ssh"`. In contrast, `services [api.Name]` above finds the declared definition. Remove references before removing a definition. For transitions between bindings, keep both the management path and the data-plane access restrictions valid at every step.

**Asymmetric SSH routing:** a reply route, a local address on one NIC, or one successful SSH connection is not proof that new connections enter on that NIC. With multiple plausible active links the guard checks all applicable ingress zones, including NetworkManager bindings. A separate subnet with loose reverse-path filtering is not an ingress constraint. When classification cannot be proven, use an independently confirmed management-source binding or a narrowly scoped `→ HOST` authorization for the management peer, destination and TCP listener. Do not open transit or a workload zone as a workaround. SSH source ports are ephemeral; the current client port must not be the sole grant.

**Moving a restricted source between zones is not atomic.** If the fallback could grant access, use separate confirmed applies: (1) fence the selector, (2) remove the old binding, (3) add the new binding and verify it in permanent **and** runtime state, (4) remove the fences. The recognized fences are priority `-32768`, target `CONTINUE`: `ANY → HOST` with a source DROP, and `ANY → ANY` with source and destination DROPs. If the move can bypass a host-output restriction, also fence `HOST → ANY` with a destination DROP. Use an independent management path: these DROPs include legitimate traffic from or to the moving selector. A filter fence cannot undo prerouting NAT or marks; detach the relevant translation in an earlier confirmed change, or establish a restrictive fallback first. Do not make either zone permissive to get past preflight.

The implicit `firewalld` package is a retained prerequisite. Removing the firewall configuration restores its objects and keys; it must not uninstall the daemon that enforces the remaining policy. An explicit APT `firewalld` declaration keeps its original package ownership and removal semantics. **Existing stacks:** apply the new DSL once while the firewalld block is still present, and verify `retainOnDelete: true` on the implicit package in the exported checkpoint before removing the block or destroying the stack. A destroy using only an old checkpoint cannot pick up a new resource option.

The nftables backend needs the native library but not necessarily the optional `nft` CLI package. When `nft` is absent, Dorothy asks the installed `libnftables.so.1` for the same read-only `inet firewalld` table. This path cannot execute caller-supplied commands and does not install or start `nftables.service`.

**Strict Docker deployments have a one-time in-place update**, not the six-unchanged migration described for a host without Docker. The existing `Service` URN now carries the expected fence policies as typed data. The helper checks loaded strict DNAT and the complete live policy inventory before installing a systemd gate bound to its content-addressed executable. Migrating an already active gate validates the new predicate and reloads systemd's unit definitions without restarting the active gate. The gate participates in subsequent Docker starts and restarts. This is a startup check, not continuous policing of an independently administered firewall.

A dedicated fence must be a negative-priority, exception-free DROP for transit ingress to `docker`. A legacy policy with masquerade, rich or direct pass rules, or an earlier overlapping permit is not an equivalent fence. Keep legitimate HOST authorizations in a separate policy and establish a valid fence before migrating; do not make the default zone permissive. Check preview, then verify the loaded policy and workload identity. Non-Docker hosts do not register this gate.

The supported pre-PR high-level DSL retains its unqualified names under `open Dorothy.DSL.Firewalld`. New names that would shadow host `service`, user `description` or firewall actions are qualified under `Defined` and `RichRule`. The low-level `FirewalldModel.Configuration` record gained fields: recompile consumers and use `{ FirewalldModel.empty kind name with ... }` instead of complete old record literals. This is wire/checkpoint compatibility, **not** constructor or binary ABI compatibility. Debian 13 rejects policy names longer than 18 characters; an offline Diff can plan a rename even if the old provider accepted that spelling. A successful deployment of such a policy on this native target is not promised.

**First acquisition is not a replacement.** Declare existing ports, bindings, services, metadata, rules and effective target/priority. A declaration may add features but must not drop a baseline feature just because `Delete` could put it back. To intentionally remove a previously external rule, acquire the complete baseline first; make the removal a separate reviewed update. There is no raw XML or unchecked takeover flag.

**Ambiguous Create acknowledgement.** Each non-preview Create writes a private recovery receipt under the invoking user's `PULUMI_HOME` before the first SSH request. A failed acknowledgement does not grant a later Create permission to take that generation. Recover a committed but uncheckpointed object with the ticket from the failed Create diagnostic, in the original receipt directory, project and stack: `pulumi import --protect=false --generate-code=false <type> <resource-name> fw-recover:<ticket>`. Code generation is unnecessary: keep the original F# declaration. Import observes the exact journaled owner and configuration; it will not steal another generation or confirm a pending transaction. Do not put a receipt, connection details, private keys or a full checkpoint in a review log.

If the provider process died before printing the ticket, inspect the private `keroosha-iac/firewalld` directory under the original `PULUMI_HOME`. Each JSON filename's stem is one ticket; identify the original URN and configuration locally, not by guessing the most recent file. Use the original parent and provider when importing a child resource. A corrupt or mismatched ticket is not authority to import a resource; leave it intact for reconciliation. A subsequent checkpointed Read retires a matching local receipt.

**Ambiguous legacy records.** A pre-proof pending transaction is not evidence of a working rollback policy. Likewise, the original mode of an adopted override is not derivable from an old journal lacking `baselineMode`. Do not invent a mode, delete the marker, or use `--runtime-to-permanent`. Preserve the checkpoint, journal, current disk and observed runtime; use an independent management path and the original backup to reconcile the native policy and metadata. Verify a fresh SSH connection and the original traffic controls before retiring the old ownership record. Without an independently established baseline, automatic release is refused.

### Recovery invariants and acceptance gate

1. The daemon must not depend on a successful Dorothy recovery executable to start filtering. An unsuccessful boot repair retains the reservation; its exit status is not a successful rollback. Verify a fresh boot, a live listener behind a denied path, the resulting loaded firewall, and the recovery diagnostic.
2. From the first durable intent, a reboot must restore the recorded working runtime, even if the daemon had not begun activation. A scoped inverse must not reload away another owner's live ban, change its timeout, or persist it. A candidate that cannot be reversed without losing such state needs a pre-write refusal.
3. Restored interfaces must be attributed to their actual producer and the effective zone. An interface name, a running process, or the reply route alone does not authenticate a binding. With the engine, container and NetworkManager already active, make an actual permanent change and prove allowed/denied traffic, not just a no-op refresh or a unit update.
4. Validate both the candidate and its recovery under effective IPv6 filtering, neighbor discovery, loaded service definitions, and retained ingress bindings. A timeout-backed ipset's empty userspace entry list does not prove absence of live kernel members. Releasing an ipset member or interface must not silently expose a restrictive source to the fallback zone.
5. Ownership is per logical object or key. Refuse foreign file ownership and unsafe permission changes; do not undo a native permission tightening or take ownership of another key. An authenticated committed owner of a default-valued setting exists even without an override file. Transitioning an old Docker fence must never delete the gate merely because Dorothy owns none of the running containers.

For each invariant, record the final helper digest, the native state before and after, and a control that distinguishes success from an inactive daemon, missing listener, cached neighbor or unrelated deny. Older guest records are historical evidence, not a deployment of a later binary.

### Operator recovery without adopting someone else's rules

Use a console or independently routed rescue channel. Preserve the private checkpoint, owner journal, global reservation, file bytes/mode/owner and the live native policy before intervening. `firewall-cmd --state`, `--get-active-zones`, `--get-default-zone`, `--info-policy`, `--query-panic`, `journalctl -b` for the boot/postboot/rollback units, and `systemctl status firewalld.service` are observations, not repairs. Do not publish tokens or private management coordinates.

* **Boot repair failed:** a weak, ordered preboot dependency allows the packaged firewall to start even when its recovery executable is missing. With a still-reserved transaction and a failed boot/postboot check, a separate unit uses the packaged `firewall-cmd --panic-on` before the normal network-pre barrier. This deliberately can deny remote SSH; console access is required when the working policy cannot be authenticated. It is not a replacement for a functional native firewall/kernel. Restore the exact trusted helper or the conflicting file/metadata from an independently verified backup; do not clear the evidence to get a green boot. Re-run recovery, verify the reservation is resolved and the configured zone/policy, then release panic mode from the console and check fresh SSH **and a denied listener**. A failure with no reserved transaction does not disable the native daemon or introduce a new permit.
* **Pending conflict:** compare only the reserved target or key, owner and before/after projections. If a third-party edit is legitimate, have its owner and the firewall operator reconcile that exact conflict out of band. Restore a verifiable preimage, run `systemctl start keroosha-iac-firewalld-rollback.service`, and observe its exit status, fresh connections and journal transition. Never delete the global marker, overwrite another owner's journal, copy runtime-to-permanent, or turn an unknown mode into `0644`.
* **Interrupted scoped undo:** the global journal records the boot generation, the count of inverses remaining and any inverse command already in flight. A completed removal is not permission to remove an identical rule reintroduced later. An unacknowledged command (including exit zero with a warning) is not retried solely because the selector is present or absent. This can leave a candidate restriction in runtime until console reconciliation or an ordered recovery reboot. Preserve the reservation; inspect the actual rule, other controller's timer, receipts and both management paths. Do not delete or refresh a foreign timed rule. Old forward-only receipts are not evidence that no inverse has previously run.
* **External Docker during containment:** a working firewall and restored SSH do not establish engine availability. Docker 26 has reported `PANIC_MODE` while programming its default bridge during a containment boot and subsequently reported two network IDs for the same bridge name. A readiness timeout is not the cause; the journal did not establish who persisted either ID. Keep panic protection, use the console, and involve the engine owner. Dorothy does not mask/restart an external engine, edit its units or network database, or promise that its containers will automatically return. Any coordination of a separately declared Dorothy Docker gate is a distinct design; an external service requires explicit owner opt-in.
  In a matched Debian control without Dorothy, enabling panic **after** the engine and container were healthy stopped new host-to-container HTTP, not the process or its internal HTTP service. Turning panic off restored external HTTP. After ordinary reboot both the control and panic arms served HTTP with the original container; both acquired a new bridge network ID. This does not explain a cold engine start under containment or assign authorship of a persisted network record.
* **Foreign live state:** runtime selector repair is not the same as a global reload. For a change which requires reload, wait for a timed ban to expire naturally, have the responsible controller persist a genuinely permanent policy, or schedule a coordinated maintenance window. Do not remove a ban or disable its controller merely to pass preflight. Runtime legacy direct rules are inspected only for comparison; Dorothy never applies or synthesizes those commands. Timeout-backed kernel sets cannot be certified empty by `--info-ipset` alone.
* **Security-key mismatch:** compare the effective system file and loaded native default zone, backend, strict DNAT and IPv6 reverse-path rules. Resolve the independently staged key with its owner first. An SSH exception does not override IPv6 reverse-path filtering. If exact backend state cannot be distinguished, use an independent management path to restore a coherent, natively validated configuration before retrying; a preview or active process is not that proof.
* **Lost local receipt / unknown legacy baseline:** restore the exact private receipt directory or an authenticated checkpoint backup. No unverified operator may manufacture a ticket from a resource name. If all such evidence or the original file mode is lost, automatic import/release is intentionally unavailable: independently reconcile host and stack ownership before using Pulumi's supported state-management tools. A policy name too long for this daemon may be renamed in offline Diff; Read/Delete do not pretend to find a valid 19-character native policy. Verify absence of the old native object **and** journal before retiring any stale checkpoint entry.
* **Existing stock public zone / engine-only workloads:** first acquisition of an existing stock zone must include effective target and vendor features, including metadata, `dhcpv6-client` and forwarding where present. Strict Docker validation applies to the engine even with zero Dorothy-owned containers. A now-ineligible old fence must be corrected on its existing URN before migration, never silently deleted. If an immutable helper is evicted from cache, the Docker gate refuses start until the exact verified helper is restored; do not disable the gate.

## Implementation and acceptance matrix

| Native capability | Public declaration / wire | Helper and Read contract | Required evidence |
|---|---|---|---|
| Zone and policy identity, version, short, description, target, priorities | Existing zone/policy objects plus explicit typed fields; preserve existing inputs | Validate object-specific fields; compare complete permanent override, separately observe live packet selectors | Old checkpoint preview; metadata drift; native input rejection |
| Interfaces; address/CIDR, MAC and ipset source bindings | Zone interfaces and source selectors; separate named ipset | Check source and interface conflicts, effective management path and live bindings | IPv4 and IPv6 source isolation; unrelated source succeeds; conflicting binding refused |
| Policy ingress, egress, `HOST`, `ANY`, priority, masquerade; zone forward | Directional policy, zone forward unchanged | Distinguish inbound local traffic from forwarding and replies; enforce each intermediate transition | Host-only permitted service, denied sibling port, other-zone traffic remains dropped |
| Service/port/protocol/source-port; service include, destination, helper and module | Named service object and references from both consumers; port/range + TCP/UDP/SCTP/DCCP | Definition before reference, reverse order on removal; reject unresolved/cyclic include; external service read only | Shared service used twice, missing dependency fails before reload |
| Rich family, priority, inverted source/destination, service, port, source-port, protocol, ICMP, NAT, logging/NFLOG, audit, limits and actions | Structured constrained rule parts (no raw XML); preserve branch and sequence | Compare full rule and provenance; refuse an ambiguous change affecting actual management, allow provably disjoint changes | Matching/nonmatching ingress; management interception refused before write |
| Forward-port and masquerade | Separate original port/transport and destination; zone or policy scope | Verify native rules after activation; strict forwarding independent of service allowance | Declared translation works, adjacent port remains closed, strict mode survives reboot |
| ICMP block, inversion, ICMP type and conntrack helper | Named definitions and references, ICMP destinations and helper module/family/ports | Only valid kinds can use each field; definition lifetimes independent of references | Native catalogue and load; no deletion of vendor definitions |
| Ipset type, options and entries | Named set, explicit typed native options and entries | Manage one set, not foreign/dynamic membership; reject ambiguity rather than claiming external changes | Bound set directs expected sources; foreign sets remain unchanged |
| `DefaultZone`, `LogDenied`, `StrictForwardPorts`, `ReloadPolicy`, `FlushAllOnReload` | One settings resource per key; old strict resource identity unchanged | Edit only owned key, distinguish missing vs explicit; preflight candidate default zone and confirm a fresh SSH connection | Observe daemon state and traffic after activation and reboot; delete restores key baseline |
| `CleanupOnExit`, `CleanupModulesOnExit`, `IPv6_rpfilter`, `IndividualCalls`, `FirewallBackend`, `RFC3964_IPv4`, `NftablesFlowtable`, `NftablesCounters`, `NftablesTableOwner`; compatibility keys `MinimalMark`, `AutomaticHelpers`, `AllowZoneDrifting`, `Lockdown` | Closed catalogue, native value grammar; document ineffectual/deprecated keys rather than invent behavior | Stage settings; choose appropriate daemon activation; preserve unrelated text; filesystem alone does not establish runtime behavior | Per-key native catalogue, restart-only setting, unrelated key edit and restoration |
| Takeover, drift, rollback and delete | Existing generation and journal plus guarded activation | Never silently erase unrepresented baseline, never capture runtime-to-permanent; read does not repair. Independently armed recovery before mutations and fresh SSH confirmation after apply/delete | Original override restored including bindings, no foreign deletes; disconnect/reboot recovery; runtime-only vs permanent drift |

Out of scope: legacy direct/passthrough rules, arbitrary nftables or shell commands, sysctls and management of other software's runtime rules. They are not an extension mechanism. The acceptance environment is a disposable guest and file backend; transport and traffic checks must not change the workstation firewall. A compiled catalogue, native load, runtime read and packet probe are different evidence. Record each separately; unsupported or untested behavior is not a pass.

### Native catalogue notes

Native packet and parser acceptance can differ. On the Debian 13 nftables backend a positive-priority `ANY → HOST` policy translated a test TCP port to a listening local port. The same forward-port in a positive-priority, concrete `public → HOST` policy passed `--check-config` but **failed native activation** (missing nftables chain); there is no packet result for the rejected rule. An independently tested positive-priority `public → HOST` rich DROP did block a listener even with zone target `ACCEPT`.

To export the catalogue from a compiled public consumer, set `DOROTHY_FIREWALLD_CATALOGUE_DIR` to a new empty directory and run `dotnet test tests/Dorothy.Tests/Dorothy.Tests.fsproj --filter FullyQualifiedName~ExportsPublicFirewalldNativeCatalogue`. Copy that directory and `scripts/check-firewalld-catalogue.pl` to a disposable Debian 13 VM with `firewalld` and `libxml-parser-perl`. Run `sudo perl check-firewalld-catalogue.pl GENERATED-DIRECTORY` **inside the guest**. This compares against the guest's installed parser dictionaries, ipset types/options and daemon keys before running `firewall-offline-cmd --check-config` on the generated tree; it does not reload the firewall.

On Debian's 2.3.1 native oracle, the compiled consumer produced all 202 supported features out of 210 declarations. The eight printed exclusions are deprecated identity, family, `immutable` and masquerade spellings, not additional enforcement capabilities. A passing catalogue says nothing about actual packet delivery, loaded settings or SSH rollback.

* The filename identifies a definition. The old root `name` and zone `immutable` attributes have no authority in 2.3.1. A split zone is a merge of several files, not several independently removable owners of one live zone. Do not discard unrecognized fragments when adopting an existing configuration.
* Zone attributes `ingress-priority` and `egress-priority` classify traffic; policy `priority` orders policies. Rich-rule `priority` orders rules. Equal rich priorities do not imply source-file order on the wire. A trailing `+` on an interface is a kernel prefix match (`eth+` matches `eth0`), not the literal interface name `eth+`.
* Native rich selectors are `source` (`address`, `mac` or `ipset`) and `destination` (`address` or `ipset`), optionally inverted. A rule has at most one service, protocol, port, source-port, ICMP block/type, masquerade, forward-port or `tcp-mss-clamp` element. Actions include accept, reject with optional type, drop, or mark with optional mask. `log` and `nflog` are alternatives; NFLOG has group, prefix and queue-size. An action, log or audit can have its own limit (`value`, optional `burst`). Ordinary zone MAC bindings use the native `source address=` form; rich rules use `source mac=`.
* The 2.3.1 ipset catalogue has `hash:ip`, `hash:ip,port`, `hash:ip,port,ip`, `hash:ip,port,net`, `hash:ip,mark`, `hash:net`, `hash:net,net`, `hash:net,port`, `hash:net,port,net`, `hash:net,iface` and `hash:mac`. Its create options are `family`, `hashsize`, `maxelem` and `timeout`. Kernel/backend support and the ability to use a set as a zone source are narrower than the catalogue. A timeout-backed runtime set is not a declaration of expiring entries.
* A service's old `<port port="" protocol="…"/>` notation maps to a protocol, not port zero. An ICMP type's `destination` activates address families; a service's `destination` constrains addresses. The helper `module` identifies a kernel conntrack helper (`nf_conntrack_…`); arbitrary module paths or module installation are not part of the API.
* `MinimalMark`, `AutomaticHelpers`, `AllowZoneDrifting` and `Lockdown` are compatibility settings, not controls to rely on for traffic enforcement. `FlushAllOnReload` selects native reload semantics: an operator cannot rely on ephemeral entries surviving a reload or reboot. Dorothy must not use `--runtime-to-permanent` to make a comparison pass.

### What a refresh can establish

`actual` remains the permanent object XML or effective setting value. `permanentInSync` includes the permanent comparison and the resource's ownership record. `runtimeObserved` and `runtimeInSync` describe the native runtime check separately. `inSync` is the provider's repair signal; a pending transaction is never in sync. Preview does not attempt any observation.

| Daemon key | Runtime evidence or limit on 2.3.1 |
|---|---|
| `DefaultZone`, `LogDenied` | Their `firewall-cmd --get-*` answers come from the running daemon. |
| `FirewallBackend`, `StrictForwardPorts` | Identify the loaded backend and its own rules. In strict nftables mode, input, forward and output DNAT each jump to a scoped chain ending in rejection; in non-strict mode the generic DNAT acceptance is present. A setting in the file alone is not evidence. |
| `NftablesCounters`, `NftablesTableOwner`, `NftablesFlowtable` | Inspect counters on rules, flags on `inet firewalld` and flowtable interfaces. These checks concern the nftables backend, not iptables. |
| `IPv6_rpfilter` | Match the daemon's enable bit to its actual IPv6 FIB-drop hook and flags (or IPv6 iptables mangle PREROUTING rule). Unrecognized or contradictory shapes cannot authorize reload. A new input reverse-path restriction cannot be justified by one existing IPv6 SSH route. |
| `IndividualCalls`, `CleanupOnExit`, `CleanupModulesOnExit`, `FlushAllOnReload`, `ReloadPolicy`, `RFC3964_IPv4` | Key-specific ownership and successful activation can be recorded. There is no exact public live value to assert. |
| Deprecated/ignored keys | A persisted spelling does not create a traffic or security guarantee. |

For a key without an exact getter, `runtimeObserved=false` and `runtimeInSync=false` distinguish a confirmed activation from a measured live value. Failure to query an observable setting must not silently count as a successful observation. A named object's live query concerns firewalld's selectors, not every rule in the kernel. In particular, independently administered policies and other packet filters may change actual reachability; use packet probes for that claim.

The host lock coordinates Dorothy writers, not other administrators, NetworkManager, or the daemon's own runtime API. Native validation, selector observation and reload are separate operations. If attribution no longer holds, recovery retains its journal rather than erasing foreign state; no atomic transaction with arbitrary external writers is claimed.

### Recovery decisions

For scoped object and runtime-only changes, the writer asks two separate questions: **may it issue another native inverse?** and **has it verified the working preimage so it may finish owner cleanup?** A zero cursor answers only the first. The global reservation carries both receipts, scoped to one boot; live state is not a lock on other controllers.

| Recovery phase and evidence (first applicable row) | Native operation | When may owner cleanup proceed? |
|---|---|---|
| Preboot | Restore only the reserved disk preimage and record that postboot verification is pending. A new boot invalidates the previous boot's inverse receipt. | Never in this phase when runtime recovery is needed. |
| Active retry while awaiting ordered postboot, with no reverse receipt from this boot | None. Active recovery cannot infer what the new daemon loaded. | Wait for ordered postboot. |
| Same boot, inverse in flight without acknowledgement | Do not repeat it, even if its selector is present. | Quarantine; ambiguous membership is not ownership. |
| Same boot, zero remaining and working preimage already verified | None; neither an observation nor a foreign rule can replenish authority. | Finish cleanup from the recorded observation. This is not a claim that live state is frozen. |
| Same boot, zero remaining but preimage **unverified** (including v4 zero receipts) | Read only. Compare the complete owned working projection, not just the touched selectors. | Only after successful verification is persisted. If an unrelated grant is missing, retain the reservation on **every** retry; its owner reconciles it. Do not recreate it, flush runtime, or remove a foreign restriction to make the check pass. |
| Active, no prior reverse receipt, forward pristine (zero completed, none in flight) | None. The helper never issued a native change. Leave independently changed selectors alone. | After the disk/owner preimage is handled. Do **not** claim to have restored live policy. |
| Active, forward command in flight with no confirmed outcome | Do not infer ownership from apparent success or failure. | Quarantine; use ordered boot/console recovery. |
| Active with confirmed forward progress, or an existing nonzero reverse cursor | Invert only an exact, attributable checkpoint; journal each inverse before and after the native command. An observed zero on first recovery retires write authority durably before full verification. | Require the full working preimage, then persist verification. A differing intermediate cursor is not permission to replay. |
| First ordered postboot, no reverse receipt | For object-delta expect the restored disk preimage. For runtime-delta accept the authenticated disk-loaded candidate and invert it, **or** retire a separately observed zero without a write, even if no forward command ever ran. Other checkpoints do not authenticate startup. | Persist boot-specific retirement **and** successful verification before fallible owner cleanup. A retry cannot turn a later identical rule into a new startup observation. |

| Change or interruption | Recovery contract |
|---|---|
| Existing zone/policy or static set | Measure membership of the **touched** selectors before staging. A preexisting timed DROP with the same native identity is not ours: refuse instead of adopting it, resetting its deadline or removing it on rollback. The independent recovery journal distinguishes commands verified complete from a command whose outcome is unknown. An ambiguous in-flight result requires reconciliation, not a guessed inverse. |
| Reverse progress and repeated recovery | The phase/receipt table above applies to both scoped strategies. A confirmed inverse is not proof that untouched selectors were restored. |
| More than one management listener | Do not use just the current SSH tuple as evidence for a default-zone switch. Compare admission for all applicable live management endpoints or conservatively compare all TCP admission if applicability cannot be proven. The supported native inventory and bind/port checks concern host TCP listeners, not all possible external tunnels. |
| Acquiring a live interface | One reachable SSH listener or a UDP grant does not establish TCP admission for the other listeners. Without a scoped inverse, require equivalent admission across affected dispatch or an unconditional grant for every applicable listener, including grants shared between simple native service definitions and explicit ports. A missing socket inventory is not an empty set. |
| Running executable replaced on disk | A deleted or unresolvable executable is not evidence that its listener is an application port. Keep it in the possible management set when deciding whether a shared service can be edited without first migrating its consumers. |
| Pre-release journal from a different helper | A v2 runtime repair has no native progress receipt. Do not assume that an active retry or a reboot grants permission to replay it. Preserve the reservation and use the documented console recovery procedure if a supported migration cannot prove the prior state. An intermediate live checkpoint different from the recorded completed count also needs reconciliation, not a guessed partial undo. |
| LOG/NFLOG without a terminal action | An application-port rule can log without permitting, denying or steering packets. Preserve its selector and logging attributes across Update, rollback and release; a separate native grant or default policy determines the packet verdict. |
| Binding a restrictive zone | An IPv4 source zone can have a different target and application ports from the default and still unconditionally grant management TCP. Verify candidate admission and affected native policy dispatch; a successful SSH on the staging path alone is insufficient. If a structural creation would narrow another path, first confirm the unbound zone, then change its source binding with a target-scoped inverse. Service removal and source release still obey reference/transfer fences. |
| Shared service / policy steering | An inbound service port change proved disjoint from the management listener can apply without detaching consumers. The same port number is not necessarily disjoint from an outbound connection's client port. When a shared definition could affect management, use a separate definition and migrate references. For a new policy whose steering could change an alternate SSH path, confirm neutral endpoints before adding the scoped selector. |
| Multiple local forward-ports | A group of additions (or removals) can use separate native receipts when the input ranges do not overlap, no destination feeds another input, and the touched object has no rich rules or masquerade. Mixed or chained steering needs individually confirmed steps or a separate safe migration. The CLI listing's `None` markers are never emitted as addresses or port arguments. |
| Global settings and live rules | Recheck foreign live state immediately before global activation. A `DefaultZone` change must not narrow SSH through a different default-zone dispatch. An IPv4 rescue connection does not authorize tightening input `IPv6_rpfilter` on a host with a usable IPv6 path: refuse before writing. Unchanged/relaxed input filtering is distinct. When only an unrelated, non-management setting remains different after disk rollback, wait for foreign restrictions to clear before flushing; never delete them. |
| Divergent permanent disk and loaded settings | Do not reload an unrelated object across the discrepancy. Reconcile the specific setting out of band or through its owner. On rollback, do not reload again when the old loaded value can already be measured directly. |
| Runtime-only repair interrupted before activation, then reboot | Boot can load the disk selector even though the interrupted process never activated it. Recover the prior working runtime from the first durable intent, not just transactions marked activation-started. |
| Pending recovery executable unavailable at boot | Start native firewalld rather than making its startup require the failed helper. A separate systemd unit requests native panic containment. Restore the authenticated executable through the console and reboot; do not delete the pending journal to regain access. This mechanism requires a functioning native firewall daemon. |
| Independently administered interfaces and expiring restrictions | An active NM profile and effective zone can establish an NM binding. A Docker-owned bridge name is insufficient: on supported rootful Linux engines, also verify that the running daemon has firewall integration enabled and subscribes to firewalld reload/restart notifications; check the prior runtime binding after activation. Missing proof refuses a flushing operation; Podman, libvirt and rootless engines are not silently treated as Docker producers. A timed ipset's empty userspace listing is not evidence of an empty kernel set. |

For Docker attribution, a missing daemon configuration with a recently changed ancestor directory is not evidence of the options the running process loaded. If provenance cannot be established, operations requiring a global flush refuse rather than assuming Docker will recreate its binding.

Recovery is deliberately not a distributed transaction with arbitrary native controllers. An already-present touched selector is different from an unrelated late restriction; a missing or ambiguous native-operation receipt cannot grant permission to remove another owner's rule. A confirmed final deletion retains the durable reservation and owner if a dependency was retargeted while waiting for confirmation; restore the exact-owned link before retrying. Early-boot panic containment still requires a global pending intent and a functional native daemon. A slow but valid inventory can delay `network-pre` rather than silently bypass recovery. Hosts with unrecognized backend rules or non-attributable interface producers refuse global reload. A currently absent interface selector is not proof of the placement of a future interface; select its permanent fallback before removing it.
