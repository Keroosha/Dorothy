# Traefik native dynamic configuration

Target: [Traefik 3.7.16](https://github.com/traefik/traefik/tree/v3.7.16). Admission is pinned to the tagged Go dynamic types and Paerser v0.2.2 `file`-tag behavior, with the generated [file-provider catalogue](https://github.com/traefik/traefik/blob/v3.7.16/docs/content/reference/dynamic-configuration/file.yaml) as a cross-check rather than the sole source. A Traefik or Paerser version change requires rechecking both. This validator establishes accepted input shape and graph safety; it is not runtime acceptance evidence.

## Boundary and references

`Dorothy.DSL.TraefikDynamic.validate entryPoints resolvers tlsOptions legacyRouters dynamicRoot` is shared with the native helper. It validates the `http`, `tcp`, and `udp` subtrees. The dynamic root allows only `http`, `tcp`, `udp`, and `tls`; `tls` is intentionally handed to the TLS validator without inspection here.

Object-map names are bounded ASCII identifiers (the native validator permits 1–128 characters). References accept an unqualified local name or explicit `name@file`, which resolve to the same object; all other provider qualifiers, including `@internal`, are rejected as unresolved. HTTP routers require a nonempty rule and are exactly one of a service leaf or a no-service parent with children. Root HTTP routers require explicit TCP entry points; children use one or more local `parentRefs` and omit `entryPoints`, `tls`, and `observability`. Child rules and middleware remain separate: parent middleware runs before child rule evaluation, and rules/middleware are not flattened. TCP routers require a rule, service, and explicit TCP entry points; UDP routers require a service and explicit UDP entry points. The private `keroosha-admin` listener/router is reserved. Native HTTP router names may not collide with legacy routers; the generated `keroosha-backend-` service and `keroosha-redirect-` middleware namespaces are reserved.

HTTP and TCP routers validate ordered middleware references. HTTP service-level middleware is a separate ordered `http.services.<name>.middlewares` array, not a load-balancer or router field. HTTP chain arrays, service compositions, and service-to-middleware references contribute typed edges; the validator rejects missing targets and service/middleware cycles, including unreferenced objects. HTTP `parentRefs` are checked as an ordered router graph with missing-parent and cycle rejection; inheritance remains Traefik's runtime behavior rather than a flattened copy. TCP and UDP weighted services resolve only same-protocol services. HTTP `errors.service` is a typed HTTP service reference. HTTP and TCP load balancers resolve only their same-protocol `serversTransports` maps. Router `tls.options` resolves to a declared option or built-in `default`; `tls.certResolver` resolves to a configured resolver. Certificate, store, and TLS-option bodies are the TLS validator's responsibility.

## Upstream and host-access restrictions

Native fields cannot install plugins, evaluate templates, or select arbitrary host files. References are local and typed; unqualified names and explicit `name@file` qualifiers resolve to the same local object, while other provider qualifiers fail. HTTP upstream URLs are absolute `http`, `https`, or `h2c` URLs without user information or fragments; pinned [SmartBuilder](https://github.com/traefik/traefik/blob/v3.7.16/pkg/proxy/smart_builder.go) explicitly routes `h2c` targets through its regular HTTP/2-capable proxy builder. TCP and UDP upstream addresses are host-and-port values, not URLs or filesystem paths.

HTTP and TCP server-transport TLS always keeps certificate verification enabled: `insecureSkipVerify: true` is rejected. `rootCAs` and ForwardAuth `tls.caCertificate` accept either an existing legacy certificate name or validated inline public `CERTIFICATE` PEM; private-key PEM, paths, and malformed PEM are rejected. Server-transport `certificates` uses only `[{certificate: <legacy-name>}]`, and ForwardAuth `tls.clientCertificate` uses only a legacy name; the TLS validation pass checks reference existence. TLS protocol bounds are limited to TLS 1.2 and TLS 1.3. The TCP server transport can set an explicit `tls.serverName` for upstream SNI and can send PROXY protocol v1 or v2; the TCP load balancer's outgoing `proxyProtocol.version` is also supported. These are upstream settings, independent of trusted inbound PROXY peers on entry points.

Fields that can read arbitrary files are not exposed: this includes HTTP basic/digest `usersFile`, Redis TLS, native ForwardAuth `ca`/`cert`/`key`, and transport `certFile`/`keyFile`. Instead, transport client certificates use `certificates: [{certificate: <legacy-name>}]`; ForwardAuth TLS uses `caCertificate` (public PEM or legacy name), `clientCertificate` (legacy name), `insecureSkipVerify`, and `caOptional`. A cross-boundary TLS validation pass checks every logical name against the configured legacy certificates before the transform resolves protected paths. File-backed or code-executing extensions such as plugins, template snippets, provider-specific middleware, and unrecognized additions fail closed. Direct provider-internal references from native user declarations are rejected; only the private lowerer emits the exact `api@internal`/`noop@internal` targets, carried by `LoweredGraph` trust metadata. The helper rejects native URL/address destinations that reach its configured admin listener.

## File-exposed fields not admitted

`http.models` is file-visible in the Go type but has no router selector. Traefik 3.7.16 `applyModel` consumes only entry-point model keys in the reserved `@internal` namespace; ordinary file-provider models are qualified as `@file` and do not affect routers. User declarations therefore reject `http.models`; no user declaration can populate Traefik's internal entry-point models. `Model.Middlewares`, `Model.TLS`, and `Model.Observability` are file-visible but do not provide an alternate inheritance path; `DefaultRuleSyntax` and `DeniedEncodedPathCharacters` are `file:"-"` and excluded.

SPIFFE `ids`/`trustDomain` fields are file-visible on HTTP/TCP dynamic transports, but their runtime use depends on a static Workload API socket and SPIFFE identity lifecycle that this configuration boundary does not model or verify. They remain rejected rather than admitted inertly; no arbitrary local socket path is exposed. `TCPServer.port` is also file-visible through Paerser despite `json`/`toml`/`yaml` exclusion, but it is provider-derived: core file routers use `address`, and the validator rejects the unused `port` form.

`HTTP ForwardingTimeouts.readTimeout` and `writeTimeout` are file-visible despite their JSON/YAML/TOML `-` tags and are admitted as durations. By contrast, `http.models`, `spiffe`, `plugin` (an unbounded arbitrary map), provider-derived TCP `port`, and fields excluded with `file:"-"` are not admitted. The generated `keroosha-admin` router and `api@internal`/`noop@internal` references are accepted only inside the renderer-produced merged graph with lowerer-owned trust metadata; caller-provided native dynamic declarations cannot claim them.

An explicit TCP `loadBalancer.serversTransport` owns outgoing PROXY and termination-delay settings. If the named transport is present, setting deprecated `loadBalancer.proxyProtocol` or `loadBalancer.terminationDelay` is rejected because Traefik ignores those load-balancer values; configure the effective values on `tcp.serversTransports.<name>`. Without a named transport, the deprecated load-balancer fields remain accepted.

Non-wildcard literal `HostSNI` rules require a TCP TLS router. The wildcard `HostSNI` catch-all may be non-TLS. A passthrough router cannot declare `tls.options`, `tls.certResolver`, or `tls.domains`, because Traefik ignores termination policy for passthrough.

Two UDP routers cannot own the same entry point, including overlap through a multi-entrypoint router; the validator rejects the graph before configuration mutation. Check receives only fixed failure categories—unresolved reference, listener protocol mismatch, UDP listener overlap, or named-transport placement—and no input names or values. Canonical lowering separately reports router, service, or middleware name collisions and HTTP/object-map type conflicts without echoing names or values.

## Tests and acceptance

`TraefikDynamicTests.fs` covers mixed HTTP/TCP/UDP graphs, ordered router/chain/service middleware, multi-layer `parentRefs`, service graph edges/cycles, typed diagnostic categories, UDP listener ownership, named-transport PROXY/termination-delay placement, native TCP health checks, passthrough/TLS conflicts, literal `HostSNI` admission, extended file-exposed middleware fields, exact provider/path exclusions, and merged-graph resolution of native service/middleware references to lowered legacy objects while rejecting `@internal` and admin spoofing. `TraefikCatalogueTests.fs` covers typed serialization without flattening parent rules or moving service middleware into the load balancer. The standalone guest snippet `tests/Traefik.Acceptance/native-dynamic-graph-check.sh` probes a header-selected child route and service-level response middleware. These tests establish validator behavior only; runtime acceptance remains a separate isolated guest gate.

## Effective route comparison

The helper compares `/api/rawdata` with the configured dynamic graph after projecting the pinned runtime transformations; it does not require rawdata to retain the input router count or names. The projection follows Traefik 3.7.16 [`mergeConfiguration`](https://github.com/traefik/traefik/blob/v3.7.16/pkg/server/aggregator.go#L20-L82) and [`applyModel`](https://github.com/traefik/traefik/blob/v3.7.16/pkg/server/aggregator.go#L348-L400): root routers inherit the default entry points when omitted, entry-point middlewares prepend router middleware, entry-point TLS is inherited only when the router has no TLS block, and modeled multi-entrypoint routers become `<entrypoint>-<router>` copies. `parentRefs` are qualified and expanded to the projected parent names. The comparison uses configured static entrypoint models in a runtime check and the live `/api/entrypoints` model for the dynamic-only API check.
Root-router observability is projected per field (explicit router value, then entrypoint model, then native default); child routers do not inherit the model or root defaults, and an observability-only entrypoint model still triggers multi-entrypoint splitting.

For example, a router configured on `a` and `b` with `entryPoints.a.http.middlewares: [common@file]` projects as `a-site@file` and `b-site@file`, each with `middlewares: [common@file, site-auth@file]`; a child of a two-entrypoint parent reports both projected parent names in `parentRefs`. A service's `middlewares` remains at the HTTP service root beside its selected service strategy. `customRequestHeaders` and other literal maps are compared by exact key and value, even when a literal header key is named `middlewares`.
The pinned Go types expose these at `dynamic.Router.ParentRefs` and the root `dynamic.Service.Middlewares`: [http_config.go](https://github.com/traefik/traefik/blob/v3.7.16/pkg/config/dynamic/http_config.go).


Priorities are compared as effective routing values: HTTP priority defaults to the UTF-8 byte length of the rule; TCP uses the same default except the exact `HostSNI('*')` catchall priority is `-1`. Explicit priority zero has the same effective value as omission. These rules are implemented in the pinned [HTTP router manager](https://github.com/traefik/traefik/blob/v3.7.16/pkg/server/router/router.go) and [TCP muxer](https://github.com/traefik/traefik/blob/v3.7.16/pkg/muxer/tcp/mux.go). Duration strings compare by elapsed nanoseconds, while omitted zero-valued booleans and known load-balancer defaults normalize only where the native type has that default. Unknown file-provider resources or literal-map entries remain drift; this is not a general missing-field exemption.

Rawdata entries are keyed by qualified names such as `a-site@file`; routers expose effective `entryPoints`, ordered `middlewares`, computed `priority`, `status`, and (for child routers) qualified `parentRefs`. HTTP services expose `middlewares` beside their service configuration. The helper uses `usedBy` as Traefik populates it, not as a generic reverse-reference index: [the pinned `PopulateUsedBy`](https://github.com/traefik/traefik/blob/v3.7.16/pkg/config/runtime/runtime.go#L128-L194) records router middleware references, including duplicate references from one router, but not chain-child or service-level middleware relationships; TCP middleware `usedBy` is not populated from TCP-router attachments. Thus a chain child is not expected to list its parent, and an attached TCP middleware is not expected to list its router.

The minimal API fixture in `TraefikBackendTests.fs` reproduces two entrypoint models, split routers, inherited TLS and middleware, a chain and child, a service-level middleware, duplicate `usedBy`, a literal header named `middlewares`, a TCP middleware attachment, and a catchall priority. The native guest case additionally captures the complete `/api/entrypoints` objects (`name`, `address`, and effective entrypoint settings) and `/api/rawdata` objects from the pinned binary; a name/address-only entrypoint list is insufficient to derive inherited router values.

This comparator is still not a traffic proof. Traefik 3.7.16 rawdata does not expose root TLS option/store bodies or named server-transport bodies; those remain tied to the authenticated loaded generation and are not individually read back from this API. Guest routing checks remain necessary for backend selection and wire behavior.
