# Traefik native configuration exposure inventory

Target: [Traefik v3.7.16](https://github.com/traefik/traefik/tree/v3.7.16/pkg/config/dynamic). The machine inventory freezes the complete reachable dynamic file-provider type graph and adds explicit static and ACME/TLS subtree classifications; the detailed static/ACME field matrices remain in [Traefik-static.md](Traefik-static.md) and [Traefik-tls.md](Traefik-tls.md). Nothing here claims support for every provider or runtime acceptance of every accepted field.

Run the credential-free, standard-library checker from the repository root:

```sh
go run scripts/check-traefik-dynamic-native-inventory.go
```

The checker downloads only public raw files at pinned tags and verifies frozen SHA-256 digests. It uses `go/ast` to enumerate the transitive `dynamic.Configuration` file fields, then requires every such path to match exactly one highest-priority classification and every `file:\"-\"` field to match its explicit exclusion. Each dynamic namespace also has a frozen field-set digest over its path prefix and exact sorted type-source path/SHA set, so a new field cannot be absorbed by a broad wildcard without deliberately updating both pins. Static/ACME delegations separately pin and resolve `Static.Configuration`, `Experimental`, `OCSPConfig`, and ACME `Configuration` roots; the linked field-boundary matrices and the six-column subtree rows below classify those surfaces separately. A dynamic extraction pass does not establish static/ACME runtime support. `*` is one map key or typed slice item; `**` is any number of descendants. It runs no Traefik binary.

## File-provider exposure is not JSON exposure

The file provider calls paerser `file.DecodeContent` (Traefik's tagged `pkg/provider/file/file.go`); paerser v0.2.2 unmarshals JSON/YAML into a map, then builds metadata with `TagFile`. Its metadata lookup matches exported Go field names case-insensitively and ignores JSON/TOML/YAML/label tags for file visibility. Only `file:"-"` excludes a field; `file:"allowEmpty"` still exposes it. Embedded structs are flattened. This means `Router.ParentRefs` is file-visible despite `label:"-"`; `HTTPConfiguration.Models`, `Service.Middlewares`, `HTTPConfiguration.ServersTransports`, `TCPService.Weighted`, and dynamic TLS certificates/transports are file-visible despite label restrictions. Conversely `TCPServer.Port` is file-visible even though JSON/TOML/YAML use `"-"` because it lacks a `file:"-"` tag; UDP `Port` is explicitly file-excluded. HTTP transport `ReadTimeout`/`WriteTimeout` are also file-visible despite JSON/TOML/YAML `"-"` tags.

`Router` embeds an empty `dynamic/ext.Router`; there is no `model` selector. `ParentRefs []string` names parent HTTP routers, not models. The pinned aggregator qualifies bare names by provider and rewrites generated entrypoint routers; the runtime router tree resolves references and detects missing parents, cycles and unreachable/dead-end routes, while restricting entry points, TLS and non-metadata observability on child routers. In contrast, the `http.models` map is file-visible but file-provider models are qualified as `@file`; upstream applies entrypoint defaults from reserved `@internal` models. The bounded DSL rejects `http.models` rather than accepting an inert declaration.

`passTLSClientCert.info.issuer.organizationalUnit` is a negative type control, not an upstream path: the pinned `TLSClientCertificateIssuerDNInfo` has no `OrganizationalUnit` member (the subject DN type does). The checker rejects a source change that makes this path real; the validator must not accept it under `issuer`.

The `static.**` and `static.certificatesResolvers.**` rows below are explicit delegations to the pinned `Static.Configuration`/entry-point and ACME types. They distinguish bounded static acceptance, helper-derived `experimental.otlplogs`, rejected API/provider/experimental/SPIFFE/OCSP subtrees, and the separate ACME credential/storage boundary. The links are field matrices, not blanket runtime claims.

## Helper and Read limits

`TraefikSettings.validate` runs the shared offline validators before rendering. The helper merges native dynamic input with Dorothy's generated HTTP routes, transforms protected TLS material, writes JSON that is valid YAML to `dynamic/current.yml`, and binds the generated private-router rule to a hash of the desired dynamic generation. Read checks exact managed file bytes/ownership and the generation marker, then checks pinned API version, entry points and RawData resources. RawData supports router/service/middleware comparisons, but named server transports and dynamic TLS options/stores have no per-field API projection; those remain exact-file/generation evidence, not independent runtime field acceptance. A live example for one service or route does not upgrade the rest of its row from validator-only to live-tested.
