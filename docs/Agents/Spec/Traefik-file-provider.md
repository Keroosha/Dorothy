# Traefik host and file-provider coverage

Target: [Traefik 3.7.16](https://github.com/traefik/traefik/tree/v3.7.16/pkg/config). This is a plan and acceptance ledger, not a support claim. A version bump requires a fresh comparison with the upstream static, dynamic, TLS and ACME types. Scope: one owned systemd process, one watched directory and one private observation endpoint. No new provider, plugin installation, firewall policy or arbitrary commands.

## Representation and ownership

Keep `keroosha:debian:Traefik`, its parent, name, resource ID, legacy inputs, ACME storage names and redirect/backend generation. Existing declarations need no checkpoint rewrite. New declarations contribute structured fields to an optional `configuration` input; omit this input for a legacy-only resource. Common operations build native objects; an object or field declared twice is an error, not a last-write-wins merge. Maps are unordered; arrays (for example middleware chains) preserve order. Secret/dependent Pulumi values stay secret/dependent. Validate known inputs offline; never collapse preview unknowns to defaults.

The new input is a secret JSON string in Pulumi state and an object on the private helper stdin protocol. Neither object names nor values appear in native-configuration diffs. Keep the existing resource token and provider identity; distribute the provider together with its matching Native AOT helper. An old plugin is not a fallback for new inputs. To check a migration, preview a copy of the old checkpoint with refresh disabled before pointing a stack at the new plugin.

Read returns `tlsProbeSummary` for legacy and structured resources. `legacyProbesAttempted` and `nativeProbesAttempted` count actual handshakes, not declarations. `opaqueRouterCount`, `unprobedCount` and `truncated` describe observation limits. A mandatory concrete target omitted because the wall-clock budget expired must not yield `inSync:true`. A required client certificate can prevent a probe from completing; that does not excuse checking the resolver's restart material.

The [F# consumer catalogue](../../../tests/Dorothy.Tests/TraefikCatalogueTests.fs) composes `traefikConfiguration` with the legacy `traefik` builder. For example, `httpRule (hostRule [ "shop.test" ] &&& pathPrefixRule "/items")` selects the path; `httpRouterService (httpServiceRef "catalog")` selects the named service. Rule arguments are quoted literals. Use the native rule form when supplying Traefik's actual rule language. TLS trust anchors can be public PEM without the CA signing key.

Example intended native shapes (JSON paths relative to `configuration`):

| Path | Example value | Binding |
|---|---|---|
| `static.entryPoints.front` | `{"address":"127.0.0.1:8443/tcp"}` | Add a listener, not a firewall opening |
| `dynamic.http.routers.catalog` | ``{"rule":"Host(`shop.test`) && PathPrefix(`/items`)","entryPoints":["front"],"service":"catalog"}`` | Resolve within the HTTP graph |
| `dynamic.tcp.services.echo` | `{"loadBalancer":{"servers":[{"address":"127.0.0.1:9000"}],"proxyProtocol":{"version":2}}}` | PROXY to the upstream is independent of trusted inbound peers |

## Coverage matrix and acceptance gates

Read this matrix together with the observed results below. Runtime means the pinned binary in a disposable Debian guest; file hashes, unit tests, schema checks and previews cannot establish that a listener forwarded a packet.

The authoritative dynamic inventory uses the [pinned Go types and file decoder](Traefik-dynamic-native-inventory.md). The generated [static](https://github.com/traefik/traefik/blob/v3.7.16/docs/content/reference/static-configuration/file.yaml) and [dynamic](https://github.com/traefik/traefik/blob/v3.7.16/docs/content/reference/dynamic-configuration/file.yaml) YAML examples are illustrations, not exhaustive field lists. The table below is an index; see the field-level catalogues for exclusions and the distinction between validated and exercised paths.

| Native capability | F# declaration | Wire path | Helper action | What Read can observe | Acceptance control |
|---|---|---|---|---|---|
| Static listeners and trust | `staticEntryPoint`, typed binds, legacy `listen` | `configuration.static.entryPoints` / `entryPoints` | Validate socket overlap and private admin boundary; restart changed static | All API pages; effective addresses, trust and exposed entrypoint settings | Same port TCP/UDP, 101 legacy listeners, changed forwarding decision with unchanged desired bytes |
| HTTP graph | `httpRouter`, rule predicates, named services/middleware, legacy `router` | `configuration.dynamic.http` / `routers` | Lower shorthand, resolve typed references, render file graph | Effective split/inherited or layered routers, priorities, live service/middleware associations | Opposite middleware orders, Method/Header/priority, shared service, health exclusion and subtree redirect |
| TCP | `tcpRouter`, `tcpService`, `tcpServersTransport` | `configuration.dynamic.tcp` | Reject competing or ignored settings; render raw/SNI/TLS or passthrough | Enabled routers, ordered declared middleware refs, backend service shape | Trusted input PROXY forwarded via named transport, backend-observed peer and payload, TCP middleware positive/negative |
| UDP | `udpRouter`, `udpService` | `configuration.dynamic.udp` | Enforce one router per listener; restart when its last handler is withdrawn | Loaded UDP graph, not arbitrary packet delivery | Fresh peer captured at ingress and old backend; surviving listener and rollback controls |
| TLS identities and policies | Provided server certificates, outbound-only client identities, named TLS options/store | Secret `certificates`, `configuration.dynamic.tls` and transport refs | Write protected material; register only serving identities inbound | Material and bounded real SNI; mTLS clients require a separate positive control | Wrong live leaf at target 17, accepted/rejected client to a verified upstream |
| ACME | `staticCertificatesResolver`, HTTP/DNS/TLS challenge, allowlisted DNS credentials | `configuration.static.certificatesResolvers`, `dnsCredentials`, legacy `resolvers` | Own storage and credentials, preserve prior issuer material | Config, protected account/leaf/key and applicable SNI | Private issuer, real renewal/rotation, corrupt or missing durable material with cached service still running |
| Logging and telemetry | `staticLog`, `staticAccessLog`, `staticMetrics`, `staticTracing` | `configuration.static` | Apply only allowlisted flags and native logging gate | Generation, effective exposed settings, not delivery of every event | Current local collector observations and identifiable access-log request |
| Lifecycle/compatibility | Same `TraefikInstance` | Same token and resource ID, paired helper protocol | Refuse skew, track restart through interruption, refuse foreign layout | Observational refresh; no repair on Read | Frozen checkpoint no-op without SSH, real drift/repair, bounded rollback, Delete retaining ACME |

Out of scope: alternate discovery providers and API/dashboard publishing; third-party plugins and template execution; changing service identity, binary, unit, watched paths or ACME storage; arbitrary host file access. Native field exclusions must identify the reason. Use only isolated loopback endpoints and a disposable Debian guest for acceptance; no public CA or DNS credentials.

**Pinned UDP caveat:** [3.7.16 switches only entrypoints included in the replacement handler map](https://github.com/traefik/traefik/blob/v3.7.16/pkg/server/server_entrypoint_udp.go). In the guest, external removal of the last handler removed the router from `/api/rawdata` but a fresh peer could still reach the old backend. Dorothy restarts when a managed change withdraws the last UDP handler from a still-bound entrypoint, including moving a route and restoring an earlier configuration. Read does not synthesize UDP traffic or assert that an externally changed daemon has no stale sessions.

On `85480f5`, a loopback capture saw the fresh client's unique payload at the listener and backend before withdrawal (1/1), at the listener only after withdrawal (1/0), and at the listener only after rollback of a rejected candidate which temporarily re-added that route (1/0). The second UDP listener continued echoing. Re-enabling the route restored 1/1 delivery. A separate HTTP-only update kept the same PID. The negative control is **absence at the backend**, not just a missing client response.
