# Traefik host and file-provider coverage

Target: [Traefik 3.7.16](https://github.com/traefik/traefik/tree/v3.7.16/pkg/config). This is a plan and acceptance ledger, not a support claim. A version bump requires a fresh comparison with the upstream static, dynamic, TLS and ACME types. Scope: one owned systemd process, one watched directory and one private observation endpoint. No new provider, plugin installation, firewall policy or arbitrary commands.

## Representation and ownership

Keep `keroosha:debian:Traefik`, its parent, name, resource ID, legacy inputs, ACME storage names and redirect/backend generation. Existing declarations need no checkpoint rewrite. New declarations contribute structured fields to an optional `configuration` input; omit this input for a legacy-only resource. Common operations build native objects; an object or field declared twice is an error, not a last-write-wins merge. Maps are unordered; arrays (for example middleware chains) preserve order. Secret/dependent Pulumi values stay secret/dependent. Validate known inputs offline; never collapse preview unknowns to defaults.

The new input is a secret JSON string in Pulumi state and an object on the private helper stdin protocol. Neither object names nor values appear in native-configuration diffs. Keep the existing resource token and provider identity; distribute the provider together with its matching Native AOT helper. An old plugin is not a fallback for new inputs. To check a migration, preview a copy of the old checkpoint with refresh disabled before pointing a stack at the new plugin.

Read returns `tlsProbeSummary` for legacy and structured resources. `legacyProbesAttempted` and `nativeProbesAttempted` count actual handshakes, not declarations. `opaqueRouterCount`, `unprobedCount` and `truncated` describe observation limits. A mandatory concrete target omitted because the wall-clock budget expired must not yield `inSync:true`. A required client certificate can prevent a probe from completing; that does not excuse checking the resolver's restart material.

The [F# consumer catalogue](../../../tests/Dorothy.Tests/TraefikCatalogueTests.fs) composes `traefikConfiguration` with the legacy `traefik` builder. For example, `httpRule (hostRule [ "shop.test" ] &&& pathPrefixRule "/items")` selects the path; `httpRouterService (httpServiceRef "catalog")` selects the named service. Rule arguments are quoted literals. Use the native rule form when supplying Traefik's actual rule language. TLS trust anchors can be public PEM without the CA signing key.

Example intended native shapes (JSON paths relative to `configuration`):

| Path | Example value | Binding |
|---|---|---|
| `static.entryPoints.front` | `{"address":"127.0.0.1:8443/tcp"}` | Add a listener, not a firewall opening |
| `dynamic.http.routers.catalog` | ``{"rule":"Host(`shop.test`) && PathPrefix(`/items`)","entryPoints":["front"],"service":"catalog"}`` | Resolve within the HTTP graph |
| `dynamic.tcp.services.echo` | `{"loadBalancer":{"servers":[{"address":"127.0.0.1:9000"}],"proxyProtocol":{"version":2}}}` | PROXY to the upstream is independent of trusted inbound peers |

## Coverage matrix and acceptance gates

Read this matrix together with the observed results below. Runtime means the pinned binary in a disposable Debian guest; file hashes, unit tests, schema checks and previews cannot establish that a listener forwarded a packet.

The authoritative dynamic inventory uses the [pinned Go types and file decoder](Traefik-dynamic-native-inventory.md). The generated [static](https://github.com/traefik/traefik/blob/v3.7.16/docs/content/reference/static-configuration/file.yaml) and [dynamic](https://github.com/traefik/traefik/blob/v3.7.16/docs/content/reference/dynamic-configuration/file.yaml) YAML examples are illustrations, not exhaustive field lists. The table below is an index; see the field-level catalogues for exclusions and the distinction between validated and exercised paths.

| Native capability | F# declaration | Wire path | Helper action | What Read can observe | Acceptance control |
|---|---|---|---|---|---|
| Static listeners and trust | `staticEntryPoint`, typed binds, legacy `listen` | `configuration.static.entryPoints` / `entryPoints` | Validate socket overlap and private admin boundary; restart changed static | All API pages; effective addresses, trust and exposed entrypoint settings | Same port TCP/UDP, 101 legacy listeners, changed forwarding decision with unchanged desired bytes |
| HTTP graph | `httpRouter`, rule predicates, named services/middleware, legacy `router` | `configuration.dynamic.http` / `routers` | Lower shorthand, resolve typed references, render file graph | Effective split/inherited or layered routers, priorities, live service/middleware associations | Opposite middleware orders, Method/Header/priority, shared service, health exclusion and subtree redirect |
| TCP | `tcpRouter`, `tcpService`, `tcpServersTransport` | `configuration.dynamic.tcp` | Reject competing or ignored settings; render raw/SNI/TLS or passthrough | Enabled routers, ordered declared middleware refs, backend service shape | Trusted input PROXY forwarded via named transport, backend-observed peer and payload, TCP middleware positive/negative |

| Logging and telemetry | `staticLog`, `staticAccessLog`, `staticMetrics`, `staticTracing` | `configuration.static` | Apply only allowlisted flags and native logging gate | Generation, effective exposed settings, not delivery of every event | Current local collector observations and identifiable access-log request |
| Lifecycle/compatibility | Same `TraefikInstance` | Same token and resource ID, paired helper protocol | Refuse skew, track restart through interruption, refuse foreign layout | Observational refresh; no repair on Read | Frozen checkpoint no-op without SSH, real drift/repair, bounded rollback, Delete retaining ACME |

Out of scope: alternate discovery providers and API/dashboard publishing; third-party plugins and template execution; changing service identity, binary, unit, watched paths or ACME storage; arbitrary host file access. Native field exclusions must identify the reason. Use only isolated loopback endpoints and a disposable Debian guest for acceptance; no public CA or DNS credentials.

**Runtime evidence requires outbound isolation.** Binding SSH or traffic listeners to loopback does not deny guest egress. The native product retains its documented default issuer when `caServer` is omitted; acceptance must instead require an explicit, allowlisted local issuer in the effective file before every start. Historical packet/issuer observations below do not attest outbound isolation. Compile-only CI is not clearance to run the guest.

## Before Apply: can the running configuration be restored?

Read reports drift and does not reconcile it. Before starting a new transaction on a running owned service, Apply compares the captured listener and dynamic graph with the private runtime API. A loaded router with `disabled` or `warning` status is not a healthy router, but its configuration can still identify the rollback baseline. Successful activation and a positive Read still require enabled resources.

If the private API cannot be reached, check the daemon and admin address. If a file is missing, unreadable, or does not represent the running configuration, preserve the external edits and reconcile the file and process before retrying ordinary Apply. Merely copying desired static bytes over a running process with a different trust policy is not reconciliation. A refusal before staging neither restarts the daemon nor creates a pending journal.

The transaction uses the captured bytes, not a later reread as a replacement preimage. Byte comparisons detect intervening changes; they do not lock out an unrelated writer or provide filesystem-wide compare-and-swap. Coordinate external writers. Rawdata omits root TLS and named transport bodies: the current structured renderer commits those separately inside the loaded private generation rule. This is not independent proof that a remote TLS peer is healthy or that an external file reference still has the same contents.

### First restart on an existing host

The private API cannot identify every static field (for example `log.level`). Before an Apply that may restart Traefik, including a restart needed only by rollback, the helper requires a root-owned `0600` receipt for the owner, current systemd `InvocationID`, and SHA-256 of the exact static file. It records this only after verifying a managed start. The receipt is not Pulumi state or a backup. An external restart, reboot, or external change to the file invalidates it. Matching listener addresses, a healthy request, and a successful Read do not establish it.

Upgrading the provider, preview, refresh, and an unchanged deployment do not stop the service or adopt a historical configuration. The **first restart-requiring change** without a valid receipt needs a maintenance window: back up the owned files (including credentials, privately), preserve unrelated edits and pending journals, reconcile the desired configuration with its authoritative source, and explicitly stop the owned service. Run a normal Apply with refresh, then verify backend-specific responses and the expected TLS leaf. Normal verified helper starts refresh the receipt; do not fabricate one, delete a pending journal, or use an external restart as a substitute. A restorable but already broken dynamic graph does not promise healthy traffic: inspect the activation and rollback diagnoses separately.

### Repairing a restored but unhealthy dynamic graph

A pending rollback journal is not a positive Read or a health receipt. If the helper itself started the previously confirmed static bytes, an unhealthy rollback may retain that start as evidence in the private journal. The helper correlates its systemd `StartUnit` job with the manager's completion record and the live invocation. It does not infer a start from a matching PID, leaf certificate or file on disk.

With this evidence, an Apply that changes only the dynamic file can bind one target digest to that transaction. If interrupted, retry the same declaration. The helper accepts only the saved preimage or that bound target; it does not reselect a target or restart the service. It checks the prior receipt, service identity, binary, unit, credential and certificate material before writing. A new health receipt requires full readiness. An external restart, foreign bytes, a different target, or a pre-existing journal with no start evidence does not qualify. Preserve the journal and external changes for operator reconciliation rather than deleting or editing the journal to force an Apply.

If the bound target fails readiness, the helper restores the exact dynamic preimage only when it still owns the target bytes, knows which graph is loaded, and restoration does not require a restart. It verifies the restored graph separately from its health. It does **not** unbind the target, promote an unhealthy receipt, or retry a new declaration automatically. If safe withdrawal needs a restart, the target and journal remain in place. Missing PID 1 job records (including rotation or reboot) also invalidate online recovery.

### Stopped-service operator handoff

This is a **local host administrator** operation, not a Pulumi property or a `traefik-v2` verb. Build `src/Dorothy.TraefikMaintenance/Dorothy.TraefikMaintenance.fsproj` with `dotnet publish -c Release -r linux-x64 --self-contained` (select the guest architecture), verify the binary digest, and install it separately as root-owned `/usr/local/sbin/dorothy-traefik-maintenance` mode `0700`. Do not put it in the provider bundle or grant deploy users sudo for it. Limit deployment delegation to the intended immutable helper **and exact command**; accounts already able to run arbitrary root commands or replace privileged executables are trusted administrators.

1. Back up the owned configuration, protected material, journal and state privately. Identify the owner from the resource ID in the known checkpoint, **not** from a newly observed file. Review the proposed declaration and the incident before proceeding.
2. Stop the owned `keroosha-traefik.service` explicitly in a maintenance window. Wait until stopped with no job. Record the full SHA-256 of `/etc/keroosha-iac/traefik/.keroosha-rollback.json`; do not print or edit its contents (credential snapshots are reversible).
3. As local root run `dorothy-traefik-maintenance recover-stopped "$resource_id" "$journal_sha256"`. Under the helper lock it verifies owner, digest, effective stopped unit, protected files and exact dynamic preimage or bound target. An unknown third file, incomplete historical credential preimage, or mismatched binary causes refusal; preserve and reconcile the external edit with its authoritative source. Do not rename a foreign file into a helper staging name.
4. The tool archives the exact journal at `/etc/keroosha-iac/.dorothy-traefik-recovery/<owner-hash>-<journal-sha256>.journal`, restores the saved dynamic file if necessary, then retires the pending journal. The archive is root:root `0600` under a `0700` directory; preserve or dispose of it according to secret-retention policy. Re-run the **same** command after interruption. Filesystems must support Linux `O_TMPFILE` and atomic same-filesystem rename between the recovery directory and configuration. No service start, health receipt, ACME store or resource ID change is part of this command.
5. Run normal `pulumi up --refresh`; verify backend-specific responses and served certificates before declaring recovery. Read/no-op on an old unmarked file is not authority for TLS bytes hidden by the private API. New managed writes include the loaded-generation commitment even for legacy declarations.

### Reviewed baseline at `2da8bc4`

The isolated producer run completed on one commit/helper. It distinguished a healthy backend-specific 200 across a pre-stage refusal from an already-loaded empty backend returning 503 before and after a failed candidate. The latter was repaired by a subsequent Apply, not by rollback. Delete preserved six nonempty stores by name and SHA-256. This run did **not** exercise a disabled router repair or establish attribution for rejected changes confined to opaque fields.

**Pinned UDP caveat:** [3.7.16 switches only entrypoints included in the replacement handler map](https://github.com/traefik/traefik/blob/v3.7.16/pkg/server/server_entrypoint_udp.go). In the guest, external removal of the last handler removed the router from `/api/rawdata` but a fresh peer could still reach the old backend. Dorothy restarts when a managed change withdraws the last UDP handler from a still-bound entrypoint, including moving a route and restoring an earlier configuration. Read does not synthesize UDP traffic or assert that an externally changed daemon has no stale sessions.

On `85480f5`, a loopback capture saw the fresh client's unique payload at the listener and backend before withdrawal (1/1), at the listener only after withdrawal (1/0), and at the listener only after rollback of a rejected candidate which temporarily re-added that route (1/0). The negative control is **absence at the backend**, not just a missing client response.
